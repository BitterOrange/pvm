## Highlights

- **Stop the daemon from PVM Desktop.** A button beside the daemon's state in the sidebar runs `pvm daemon stop`. The app asks first and says how many VMs are running, a VM whose provisioning failed included, as the daemon shuts them all down on its way out. The app then shows the "Start the daemon" page and does not start it again by itself.
- **Installed apps are found in the VM.** The installed list held only what `pvm app install` recorded, so an app that came with the image or was installed by hand never showed in `pvm app ls` or in PVM Desktop. A running VM is now asked which catalog commands it has, including the vendor installers' `~/.local/bin`; an app removed by hand drops out, and a stopped VM shows what was last seen.
- **Firefox in the catalog.** `pvm app install dev1 firefox` installs Mozilla's own build from its APT repository, with the signing key pinned by fingerprint as in the images. VMs from current images already have it, and the install leaves it as it is.
- **Terminal apps are listed, not started, from the app menu.** Claude Code and Codex work on the folder they start in, and the app menu would start them in the home folder. They are now shown without a click action, with a note to start them from a workspace's terminal, which opens in the matching folder.

## Upgrading

- Nothing to do beyond installing this release. `pvm upgrade` still replaces `pvm.exe` only; PVM Desktop comes with the Windows installer.

## Known issues

- Starting the daemon at a real logon, and whether a window flashes then, has not been checked yet.
- A VM whose disk was grown outside pvm keeps the old size in its record, so Resize starts from that size and a disk size between the two is refused.
