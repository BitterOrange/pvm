## Highlights

- **Change a VM's vcpus and memory.** `pvm resize dev1 [<disk-gb>] [--cpus N] [--mem MB]` changes only what it is given, on a stopped VM; the disk still only grows. A change of vcpus or memory is refused while a RAM snapshot waits to be restored, as the snapshot only restores into the machine it was taken from.
- **Resize in PVM Desktop.** Resize, in a VM's menu, sets vcpus, memory and disk and passes only what changed. A running VM is stopped, resized and started again, after the dialog says so. The vcpus are a slider here and in the Create form; it ends at the host's logical processors and warns at that count that the host can freeze.
- **App settings show the current values.** PVM Desktop reads a VM's clipboard, drop and audio settings (`GET /v1/vms/{name}/apps/config`) and passes only the ones changed.
- **Start at login without administrator rights.** Turning on "start the pvm daemon at login" failed with `schtasks create: exit status 1`: the task was set for any user's logon, which needs an administrator. It is now limited to the current user and runs `pvm daemon start`, which starts the daemon hidden instead of keeping a console window open. schtasks errors now show their reason on one line.
- **PVM Desktop polish.** The window and shortcut use the sidebar's orange cube as their icon, and clearing finished tasks closes the activity panel when nothing is left.

## Upgrading

- Nothing to do beyond installing this release. If start at login was turned on with an earlier version and failed, turn it on again. `pvm upgrade` still replaces `pvm.exe` only; PVM Desktop comes with the Windows installer.

## Known issues

- Starting the daemon at a real logon, and whether a window flashes then, has not been checked yet.
- A VM whose disk was grown outside pvm keeps the old size in its record, so Resize starts from that size and a disk size between the two is refused.
