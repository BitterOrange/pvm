## Highlights

- **The installers and `install.sh` no longer carry QEMU.** The Windows installers bring pvm, PVM Desktop and the Xpra client; PVM Desktop's QEMU page or `pvm qemu install` then sets QEMU up. `scripts/install.sh` installs pvm and then follows `PVM_QEMU`: `project` (the default) runs `pvm qemu install -y`, `official` runs `pvm qemu use official -y`, and `none` only prints both commands. If the QEMU setup fails, pvm stays installed and the script exits non-zero. The NSIS installer shrinks from 85.6 MB to 75.1 MB and the MSI from 124.6 MB to 110.8 MB. Uninstalling keeps `~/.pvm`, including the builds in `runtime\qemu\builds`.
- **`pvm-exit`, the exit server on its own.** The VPS runs a server-only binary with `/etc/pvm-exit/config.yaml`, as a system service under the unprivileged `pvm-exit` user (kernel NAT with `CAP_NET_ADMIN` and `CAP_NET_RAW` only) or, with `--user-mode`, as a systemd user service with userspace NAT and no root.
  - `pvm exit deploy my-exit --ssh root@vps.example.com` installs it over SSH, starts it and adds the exit; SSH authenticates the VPS, so no token or fingerprint is copied by hand. Without `--binary` it downloads, verifies and uploads the matching `pvm-exit`.
  - Hosts join with a one-time invite (`pvm-exit invite laptop`, valid for 15 minutes) that gives each host its own enroll token, which registers peers but cannot manage the server. `pvm-exit token ls|rm` lists and revokes them, and `pvm exit rm` revokes the host's token once it has no peer left. PVM Desktop's "add exit" menu takes an invite too.
  - Also installable with the `.deb` from the release or `scripts/install-exit.sh`. A VPS set up with `pvm exit-agent install` moves over with `pvm-exit init --migrate` (or `pvm exit deploy ... --migrate`), keeping its token, fingerprint and peers.
- **Release checks without a GitHub login.** `scripts/install.sh`, `scripts/install-exit.sh`, `pvm upgrade` and `pvm exit deploy` fetch the release attestation from GitHub's API anonymously and verify it offline with `gh attestation verify --bundle`, so `gh` must be installed but needs no account.
- **Merged from upstream v1.3.0-1.3.1:**
  - Mihomo exits: `pvm exit import` takes Clash, Mihomo or Surge YAML or share links, and `pvm exit nodes` lists the usable nodes. Mihomo runs as its own service inside the gateway VM, never linked into pvm.
  - `pvm check <vm>` gathers evidence of the VM's egress, DNS and leaks, and `pvm route require-check` keeps a VM without external traffic until a check passes.
  - `pvm diag` exports a redacted ZIP for troubleshooting, and `pvm dashboard` serves a local read-only status page.
  - `--json` on read-only commands, `pvm capabilities`, job handles with `pvm job`, `pvm ssh-config` for VS Code Remote-SSH, and `pvm default` and `pvm image default`.
  - DoH upstreams with failover in `PVM_DNS_UPSTREAM`.
  - The host-to-guest clipboard bridge for `pvm app` on macOS and Linux hosts.
- **VMs come back after a daemon restart.** `pvm daemon restart`, `pvm upgrade` and a host reboot with the login service start the user VMs that were running, and wait until they are ready; `pvm daemon stop` or `pvm stop` keeps them stopped. A VM restored from its RAM snapshot is resumed instead of being left paused.
- **The memory balloon.** Idle guest memory goes back to the host and grows again under pressure; the guest can deflate the balloon before an out-of-memory kill.
- **The timezone follows the exit.** When a VM routes through an exit, its timezone is that of the exit's public IP, probed through the exit itself; routing back restores the VM's own. `pvm exit test` checks egress only for an exit a VM routes through.

## Upgrading

- **From v1.4.0 on Windows:** rerun the installer to get the new PVM Desktop. The QEMU that the v1.4.0 installer placed is kept: pvm takes it over as a project build when the daemon starts. One case loses it: upgrading from the v1.4.0 MSI without having run pvm since installing v1.4.0 removes that QEMU with the old version. PVM Desktop then shows its QEMU page; set QEMU up again there or with `pvm qemu install`.
- **From v1.3.x:** `pvm upgrade` still works; this release carries the pinned QEMU under the names v1.3.x upgrades from. On Windows, rerun the installer afterwards to replace PVM Desktop and the uninstaller. The bridge goes in v1.5.0, so upgrade through a v1.4.x release.
- **`install.sh` from master installs v1.4.0 and later only.** For an older `TAG`, it prints the URL of that version's own script.
- **Exit servers:** a VPS running `pvm exit-agent` keeps working. Move it to `pvm-exit` with `pvm-exit init --migrate` before v1.5.0, which removes `pvm exit-agent`.

## Known issues

- No QEMU for Windows has virtio-9p, the pvm-qemu build included; host folders are mounted in WSL2 mode, or through workspaces.
- WHPX VMs have no AVX.
- Not yet tested end to end: the clipboard bridge on macOS and Linux hosts, `pvm app` windows on Windows since the upstream merge, and an MSI upgrade from v1.3.x.
- Homebrew has disabled its `xpra` cask, which fails Gatekeeper; on macOS install the Xpra 6.5 client from xpra.org.
