## Highlights

- **The keyring as a setting.** `pvm app config <vm> --keyring off|host`.
  - `off`, the default for new VMs: pvm leaves the VM's keyring alone, as upstream does.
  - `host`: the VM's login keyring is encrypted with a random password that pvm keeps on the host, and pvm unlocks it before any app starts. A keyring with a password pvm did not set is never touched: `pvm app` refuses to start apps instead.
  - Why: Claude Desktop encrypts its sign-in with a key from the keyring while it can reach it, and with Chromium's fixed key while it cannot, and a start one way cannot read what the other wrote. With `host` the keyring is always unlocked first.
  - VMs that still have pvm's earlier keyring, unencrypted with an empty password, move to `host` the next time an app starts, and keep its contents. VMs without one get `off`.
  - Measured with Claude Desktop in a migrated VM: it stayed signed in, and its messages went through, after restarting the app, the Xpra server, the VM and the daemon.
- **Window scale.** `pvm app config <vm> --scale 1|1.25|1.5|2` has the VM draw its windows at fewer pixels and the host client enlarge them. Text keeps its size and looks softer. In a 10-vCPU WHPX VM on a host at 125%, scrolling Claude Desktop drew about 28 frames a second at 1.25 against 15 to 17 at 1; 1.5 and 2 drew no more than 1.25.
- **App settings apply at once.** After a change to the clipboard, drops, audio, silence or scale, `pvm app config` attaches a connected client again. On a new scale, open windows are first resized in the VM, so they keep their size on the host.
- **No focus ring after a click in Electron apps.** Clicking a message in Claude Desktop drew a blue focus ring around it. The key pvm presses so that Chromium reports its text cursor counted as keyboard use; it is now Control, which does not.
- PVM Desktop has the keyring as a choice and the scale as a slider with a stop for each scale, in App settings and in the create form.

## Upgrading

- **Restart the VM's Xpra server** for the focus ring fix: stop the VM's apps with `pvm app stop <vm> --all`, or restart the VM.
- **The keyring password lives on the host,** in `keyring.secret` in the VM's app directory under `~/.pvm`. Keep it with the VM: without it the keyring cannot be opened, and its secrets are lost. pvm never replaces it.
- **Switching a VM from `host` to `off`** signs apps such as Claude Desktop out once the VM restarts, as nothing unlocks the keyring then.
- **Use the Windows installer** for PVM Desktop's new settings. `pvm upgrade` still replaces `pvm.exe` only.

## Known issues

- PVM Desktop's App settings scroll, and the settings below the fold are easy to miss. A new layout is on the roadmap.
- `pvm app stop <vm> <id>` can report `exit status 1` with no message although the app stopped, and an app started right after can fail while its unit is still stopping. The cause has not been looked into.
- In Chromium and Electron apps, a text cursor that moves without a click, a focus change or committed text is not reported, so the candidates stay where they were.
- On macOS and Linux hosts the candidates still open at the top left of the window, and the microphone does not follow a new default device.
- WHPX VMs still have no AVX.
